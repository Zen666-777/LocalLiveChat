# MEL Chatの完成基準

最低ラインは「会話はzetaと同等以上、記憶はさらに上」。これは開発目標であり、現時点の性能を表す宣伝文句ではありません。

## 現在の判定

**未達成・比較待ち。** 専用の追加学習済み重みはまだ作成していません。標準モデルはQwen3 4B Instruct 2507 Q4_K_Mです。テストやAPKビルドの成功だけで、この品質基準に合格したとは扱いません。

## 会話の合格条件

日本語、キャラの一貫性、感情表現、物語の進行、ユーザーの行動を勝手に決めないこと、反復の少なさを比較します。小説では視点・時制・情景と台詞の自然さも含めます。

1. 自作した同じキャラ詳細・プロット・ロアと直前の会話を用意する。
2. MEL Chatとzetaで同じ依頼を複数回試し、モデル・設定・日付・有料機能の有無を記録する。
3. サービス名を伏せて、利用者が各観点を1〜5点で採点する。可能なら表示順も入れ替える。
4. 場面別の勝ち・引き分け・負けと苦手分野を残す。総合で同等以上と判断できるまで未達成とする。

1件だけの良い出力や、自動採点モデルの好みだけを根拠に達成扱いにしません。速度・発熱・長時間利用の安定性はGalaxy実機で別に測定します。

## 記憶の合格条件

| 項目 | 検証内容 |
| --- | --- |
| 古い約束 | 100往復以上前の約束の日時・場所・内容を回答に使える |
| 訂正 | 古い情報と後から変わった情報を区別できる |
| 関係の変化 | いつ・何がきっかけで関係が変わったかを参照できる |
| 伏線 | 未回収の伏線を保持し、解決後の状態へ更新できる |
| 出典 | 参照した原文を利用者が確認できる |
| 分離 | 同じキャラでも別プロットの秘密が混ざらない |
| 不明 | 記録にない情報を捏造しない |
| 継続 | 要約・再起動・モデル切替・APK更新後も記録が残る |

原文の検索・プロンプトへの投入と、モデルの最終回答の正しさは分けて評価します。Roomのテストだけでは後者を保証しません。

## 実モデルの基準出力

`QualityFixtureTest`は架空の成人キャラクターを使う12場面を作り、実際のRepositoryで組み立てたプロンプトを`app/build/evaluation/testDebugUnitTest/requests.jsonl`へ出力します。仮の応答は入力に含めません。

Actionsは推奨GGUFを検証し、アプリと共通のC++エンジンでこの入力を実行します。`MEL-Chat-quality-baseline`アーティファクトに入力の`requests.jsonl`、生成本文と時間・トークン数の`responses.jsonl`、人が読むための`BASELINE.md`を保存します。自動で品質合格にはしません。

同じ出力集をActions実行のSummaryにも掲載するため、GalaxyのブラウザからZIPを展開せずに読めます。

これはLinux CPUの測定で、Galaxyの性能を示しません。記憶ケースは事前に用意した要約と原文を使うため、自動要約モデルの品質や長期運用を証明しません。zeta側の出力や個人の会話は収集・送信しません。

## 実装の現状と限界

- 原文は日本語文字の一致で端末内検索する。共通の文字がない言い換えや曖昧な指示は取り逃す場合がある。
- 検索候補は最大32語、希少な8語から各32件。入力へは原文を最大4件戻す。全件を同時に読ませる方式ではない。
- 記憶帳は人物・関係・出来事・約束・伏線・好みなどを利用者が個別に保存・編集する。内容の自動抽出や達成済み判定は未実装。
- 常に参照する記憶は有効な項目で最大8件。要約に上書きされない。それ以外は文字の一致で選ぶ。
- 原文の抜粋には話者と時刻を付ける。発言中の希望・推測が自動的に確定事実になるわけではない。
- 検索結果は入力予算内で追加し、設定・常時参照の記憶・直近の会話を押し出さない。
- 端末推論はCPU、文脈4096、標準返信256トークン。長い記憶と長い小説を両立するにはモデル・実行環境の改善も必要。
