# MEL RP：ローカルLLM版

## スマホだけで使う

1. 固定署名の新しい `MEL-Chat.apk` を更新インストールする。
2. 右上の設定で「端末内で動かす」がONになっていることを確認する。
3. 「推奨モデルを取得」を押す。約2.5GBを取得する。標準はWi-Fiだが「モバイル通信も使う」を選べる。APIキー・PCは不要。
4. 取得後にキャラを選び、会話する。初回はモデルの読み込みで時間がかかる。
5. 機内モードでも会話できる。自動要約も端末の同じモデルで処理する。

Android DownloadManagerで取得するため、アプリを閉じても取得は続けられる。
取得後のSHA-256確認はアプリを開いた状態で行う。不一致の重みを自動採用しない。
旧版のWi-Fi待ちの取得は「モバイル通信で最初から取得」でやり直せる。
その場合は取得済みの部分を破棄して約2.5GBを取り直す。ローミング通信は許可しない。
端末側の大容量ダウンロード制限や接続待ちは、理由に応じて表示する。
アプリからの取得が進まない場合は「ブラウザでモデルを取得」を開き、取得後に
アプリ内の取得を中止して「別のGGUFモデルを読み込む」で選ぶ。

「別のGGUFモデルを読み込む」で、マイファイルから互換性のあるモデルを選べる。
アプリが保存領域へコピーするので、元のファイルを移動しても使える。
6GB以下のテキスト用Instruct GGUF v2/v3、4096トークン以上の文脈が対象。
推論エンジンが非対応のアーキテクチャやチャット形式は読み込めない。

## 独自モデルへの工程

現在のMEL RPは、キャラの性格・口調・世界観、関係性、物語の現在地を重視した
プロンプトとアプリの制御。重みの追加学習ではない。推奨モデルの出力傾向や
成人向けRPの得意不得意をアプリだけで保証するものではない。

重みもRP向けに変える次段階は、以下の順序で進める。

1. 日本語、返信長、台詞と地の文の比率、関係性など目標の作風を決める。
2. 利用権のある創作会話で複数ターンのデータを作り、評価用を別に確保する。
3. LoRA/QLoRAで追加学習し、元モデルと同じ会話例で比較する。
4. 日本語の自然さ、設定の維持、反復、ユーザー発言の捏造、記憶の継承を評価する。
5. 良い結果を元モデルへマージし、GGUFへ変換、Q4_K_Mへ量子化する。
6. 量子化後も評価し、できたGGUFをMEL Chatへ読み込む。

学習はまだ実行していない。GPUの手配・費用・学習データの外部送信もしていない。
Galaxyだけで4Bモデルを実用的に追加学習できるとは約束しない。
作成時だけGPUを使う場合でも、完成後の会話と記憶は端末内で動かせる。
個人の会話を学習サービスへ無断送信する機能はない。

## 記憶とプライバシー

- 文脈4096トークン、返信最大256トークン、CPU最大4スレッド。
- モデルの読み込み、会話の読み取り、返信生成、記憶の要約を分けて表示する。
  返信は生成途中から表示し、完成後に保存する。停止・失敗した途中の文字は保存しない。
- 各推論呼び出しは3分を上限に中止を通知する。ネイティブ処理が中止を確認して終了してから次を実行する。
- 失敗理由は会話画面に残り、アプリを開き直しても確認できる。通知が表示前に消える不具合を修正。
- アプリ終了などで返信が中断された場合は、最後の処理段階を表示する。
- モデルのトークナイザーとチャット形式で入力を数える。
- 未要約24件超または文脈予算超過で、会話の前方を端末内で要約する。
  通常は直近8件、文脈が足りない場合は直近2件まで残してさらに要約する。
- 要約と更新位置は一緒に保存し、失敗時は位置を進めない。履歴原文は削除しない。
- 設定・記憶・直近の投稿だけで上限を超えたらエラーを出し、勝手に切り捨てない。
- 停止はモデルの読み込み・デコードにも通知する。未回答の投稿は再試行できる。
- 上限を超えた未回答の投稿は「編集」で短く直して保存し、重複させずに再試行できる。
- OpenRouterへ自動切替しない。APIキーをローカル推論へ渡さない。
- モデル取得時だけHugging Faceと配信先へ接続する。
- 会話・記憶はRoom、重みはアプリ専用の外部ストレージ領域に保存する。
  アンインストールすると消える。モデル削除やメモリ解放で会話・記憶は消えない。
- 空きメモリ、熱、電池、OSのバックグラウンド制限で速度・継続性は変わる。

## 検証

arm64-v8a向けJNIをAPKへ組み込み、固定署名を検証する。
単体テストではオフライン経路の分離、自動フォールバック禁止、モデルの取り込みと
永続化、小さい文脈での要約と履歴保持を検証する。

Actionsでは同じC++エンジンをLinux CPUでもビルドし、推奨4B GGUFのSHAを確認後、
日本語の複数ターン会話、要約、文脈超過の拒否、停止後の再試行を実行する。
さらにJava/JNI経由で同じエンジンを読み込み、文字の逐次受け取り、日本語・絵文字、
生成途中の停止、コールバックの例外、再試行を検証する。
Galaxyの速度・発熱やAndroidのファイル選択画面は実機での確認が必要。
